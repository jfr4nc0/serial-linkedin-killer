<task type="auto">
  <name>Task 2: Implement provider factory in get_llm_client()</name>
  <files>src/core/providers/llm_client.py</files>
  <action>
Rewrite `src/core/providers/llm_client.py` to implement the provider factory pattern. The complete implementation:

1. **Imports** — Add `os`, `BaseChatModel` from `langchain_core.language_models.chat_models`, and `ChatGoogleGenerativeAI` from `langchain_google_genai`. Keep existing `ChatOpenAI` and `load_config` imports.

2. **Module docstring** — Update to: `"""LLM client factory supporting local OpenAI-compatible and Google Gemini providers."""`

3. **Cache type** — Change `_llm_cache: dict = {}` to `_llm_cache: dict[str, BaseChatModel] = {}` for type clarity.

4. **Return type** — Change return type from `-> ChatOpenAI` to `-> BaseChatModel`. This is safe because all 5 consumers (`src/__init__.py`, `src/core/agent.py`, `cv_analysis_tools.py`, `role_clustering.py`, `providers/__init__.py`) only use `.invoke()` and `.batch()` which are on `BaseChatModel`.

5. **Provider resolution** — At the TOP of the function (before cache check), resolve provider:
   ```python
   config = load_config()
   provider = os.getenv("LLM_PROVIDER", config.llm.provider).lower()
   ```
   This ensures LLM_PROVIDER env var is checked at call-time, not config-load time (research Pitfall 2). The `.lower()` normalizes case.

6. **Cache check** — Check `if provider in _llm_cache: return _llm_cache[provider]` using provider-specific key (NOT "default"). This prevents cache pollution (research Pitfall 1).

7. **Gemini branch** — When `provider == "gemini"`:
   ```python
   client = ChatGoogleGenerativeAI(
       model=config.llm.gemini_model,
       google_api_key=os.getenv("GEMINI_API_KEY"),
       temperature=config.llm.temperature,
       max_output_tokens=config.llm.max_tokens,
   )
   ```
   Key decisions:
   - Pass `google_api_key=os.getenv("GEMINI_API_KEY")` explicitly to honor requirement PROV-04. The v2.1.12 SDK auto-detects `GOOGLE_API_KEY` but not `GEMINI_API_KEY`, so we bridge the gap by reading `GEMINI_API_KEY` and passing it to the `google_api_key` constructor parameter.
   - Use `max_output_tokens` (NOT `max_tokens`) — Gemini uses different parameter name (research Pitfall 5).
   - `model` is required in v2.1.12, no default (research Pitfall 4).
   - Do NOT validate API key presence — let SDK fail on first `.invoke()` with clear error (lazy validation per research recommendation).

8. **Local branch** — When `provider == "local"`, create `ChatOpenAI` exactly as current code does (base_url, api_key, temperature, max_tokens from config). This preserves backward compatibility for LLM-03.

9. **Error handling** — If provider is neither "local" nor "gemini", raise `ValueError` with message: `f"Unknown LLM provider: '{provider}'. Must be 'local' or 'gemini'. Set via LLM_PROVIDER env var or llm.provider in config/agent.yaml."`

10. **Cache store** — `_llm_cache[provider] = client` before returning.

11. **Docstring** — Update to document provider selection priority (env var > config > default "local"), supported providers, return type, and ValueError.
