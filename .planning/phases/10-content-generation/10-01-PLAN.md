  <files>src/core/utils/text_diversity.py</files>
  <action>
Create `src/core/utils/text_diversity.py` with two functions:

1. `calculate_text_diversity(text_a: str, text_b: str) -> float` -- Returns a float between 0.0 and 1.0 representing how different two texts are. Use Python's built-in `difflib.SequenceMatcher` (no external deps). Normalize both texts to lowercase and strip whitespace before comparison. Return `1.0 - SequenceMatcher(None, a, b).ratio()`. This means 0.0 = identical, 1.0 = completely different.

2. `validate_diversity(texts: list[str], threshold: float = 0.7) -> dict` -- Takes a list of generated content strings and a threshold (default 0.7). Computes pairwise diversity for all combinations using `itertools.combinations`. Returns a dict with:
   - `"passed": bool` -- True if ALL pairs have diversity >= threshold
   - `"min_diversity": float` -- The lowest pairwise diversity score found
   - `"failing_pairs": list[tuple[int, int, float]]` -- List of (index_a, index_b, diversity_score) for pairs below threshold
   - `"pair_count": int` -- Total number of pairs checked

Keep it pure utility -- no DB, no LLM, no imports beyond stdlib. Add module docstring explaining the >70% diversity requirement for spam prevention.
  </action>

Expected: First prints ~0.0 (identical), second prints >0.5 (different), third prints a dict with passed=True.
  </verify>

  <action>
Create `src/core/api/services/content_generation_service.py` following the CampaignService pattern (standalone service, `__init__(engine_or_url)`, session factory).

**Sentiment presets dict** -- Class-level constant `SENTIMENT_PRESETS: dict[str, str]` mapping sentiment name to a prompt instruction string. Define all 10:
- `"urgency"`: "Rewrite with a sense of urgency and time-sensitivity. Use action verbs, deadlines, and scarcity language."
- `"authority"`: "Rewrite as an authoritative thought leader. Use confident language, industry expertise, and data-driven assertions."
- `"calm"`: "Rewrite with a calm, measured tone. Use reassuring language, steady pacing, and thoughtful observations."
- `"empathy"`: "Rewrite with deep empathy and understanding. Acknowledge challenges, validate feelings, and offer genuine support."
- `"curiosity"`: "Rewrite to spark curiosity and engagement. Use thought-provoking questions, surprising facts, and open loops."
- `"social_proof"`: "Rewrite leveraging social proof. Reference trends, community adoption, peer success stories, and collective momentum."
- `"educational"`: "Rewrite as educational content. Teach something valuable, break down complexity, and provide actionable takeaways."
- `"provocative"`: "Rewrite with a provocative, contrarian angle. Challenge assumptions, question norms, and present bold perspectives."
- `"inspirational"`: "Rewrite to inspire and motivate. Use aspirational language, vision-casting, and empowering calls to action."
- `"humorous"`: "Rewrite with wit and humor. Use clever wordplay, relatable observations, and a light conversational tone."

**Methods:**

1. `get_sentiment_prompt(sentiment: str, custom_prompt: str | None = None) -> str` -- If `custom_prompt` is provided, return it directly. Otherwise look up `sentiment` in `SENTIMENT_PRESETS`. Raise `ValueError` if sentiment not found in presets and no custom_prompt given.

2. `generate_variant_content(base_message: str, sentiment: str, custom_prompt: str | None = None) -> str` -- Build a prompt that includes the base_message and the sentiment instruction (from `get_sentiment_prompt`). The full prompt template should be:
```
You are a LinkedIn content strategist. Your task is to create a LinkedIn post variant.

Base message:
{base_message}

Sentiment instruction:
{sentiment_prompt}

Requirements:
- Keep the core message and intent intact
- Adapt the tone, style, and framing according to the sentiment instruction
- Write for a professional LinkedIn audience
- Keep it concise (under 1300 characters for LinkedIn post limits)
- Do not include hashtags unless they naturally fit
- Output ONLY the rewritten post text, nothing else
```
Call `get_llm_client().invoke(prompt)` where prompt is a single HumanMessage string. The LLM client returns an AIMessage -- extract `.content` and strip whitespace. Return the generated text string.

Note: `get_llm_client()` returns a `BaseChatModel` (LangChain). To invoke with a plain string prompt, use: `from langchain_core.messages import HumanMessage` and call `client.invoke([HumanMessage(content=prompt)])`.

3. `generate_campaign_variants(campaign_id: str, custom_prompts: dict[str, str] | None = None) -> dict` -- Main orchestration method:
   a. Load campaign via DB session (query Campaign by id, error if not found or status != "draft")
   b. Load all CampaignVariant rows for this campaign_id where content is empty (`content == ""`)
   c. If no empty variants found, raise ValueError("No empty variants to generate content for")
   d. For each empty variant, call `generate_variant_content(campaign.base_message, variant.sentiment, custom_prompts.get(variant.sentiment) if custom_prompts else None)`
   e. Update each variant's `content` field in the DB with the generated text
   f. Collect all generated content strings, then call `validate_diversity(contents, threshold=0.7)` from text_diversity module
   g. Commit the DB changes
   h. Return dict with:
      - `"campaign_id": str`
      - `"variants_generated": int` (count of variants that got content)
      - `"diversity": dict` (the validate_diversity result)
      - `"variants": list[dict]` (each with id, sentiment, content snippet first 100 chars)

Import `get_llm_client` from `src.core.providers.llm_client`. Import `validate_diversity` from `src.core.utils.text_diversity`. Import models from `src.core.db.models`. Follow the same `create_db_engine`/`create_session_factory` pattern as CampaignService.

Do NOT regenerate variants that already have content (non-empty). This allows partial regeneration if some fail.
