Modify `CompanyDB.filter_companies()` in `src/core/agents/tools/company_db.py` to paginate
internally using SQLAlchemy's `.yield_per(chunk_size)` while still returning a `List[dict]`.

**Why yield_per instead of changing the return type:**
Both consumers in `outreach_service.py` (lines 109 and 420) call `len()`, use slicing
(`companies[:limit]`), check truthiness (`not companies`), and pass the result as a list to
downstream functions. Changing to a generator would break all of these. The memory win comes
from avoiding the peak where ALL ORM Company objects AND ALL converted dicts coexist — with
yield_per, only `chunk_size` ORM objects are alive at any time while dicts accumulate
incrementally.

Implementation details:
1. Add `chunk_size: int = 500` parameter to `filter_companies()` signature (after `filters`).
2. Replace `rows = query.all()` with iteration using `query.yield_per(chunk_size)`:
   ```python
   results = []
   columns = Company.__table__.columns
   for row in query.yield_per(chunk_size):
       results.append({c.name: getattr(row, c.name) for c in columns})
   return results
   ```
3. Update the type hint: `def filter_companies(self, filters: Dict[str, List[str]], chunk_size: int = 500) -> List[dict]:`
4. IMPORTANT: `yield_per()` requires that the session stays open during iteration. The current
   `with self._session_factory() as session:` block already covers the full method — this works
   because we iterate inside the `with` block and build the list before exiting. Verify the
   session context manager scope covers the yield_per iteration.

**No changes needed in outreach_service.py** — both `_run_search` (line 109) and `_run` (line 420)
call `filter_companies(request.filters)` and get back a list just like before. The interface is
unchanged; only the internal memory profile improves.

Modify `AgentDB.get_search_results()` in `src/core/db/agent_db.py` to yield dicts lazily using
`yield_per()` instead of materializing all ORM rows then converting all to dicts.

**Why a generator works here (unlike QUERY-01):**
The single consumer in `outreach_agent.py` line 163 (`db_results = self._db.get_search_results(batch_id)`)
only iterates with `for emp in db_results:` (line 164) and appends each dict to `all_employees`.
It never calls `len(db_results)`, never indexes into it, never checks truthiness. The `len()` call
on line 172 is on `all_employees`, not on `db_results`. So a generator is fully compatible.

Implementation in `src/core/db/agent_db.py`:

1. Change method signature return type from `list` to `Iterator[dict]`:
   ```python
   from typing import Iterator
   # ...
   def get_search_results(self, batch_id: str, chunk_size: int = 500) -> Iterator[dict]:
   ```

2. Replace the current implementation with a generator that keeps the session open:
   ```python
   def get_search_results(self, batch_id: str, chunk_size: int = 500) -> Iterator[dict]:
       """Yield employee dicts for a batch_id in chunks (memory-efficient)."""
       with self._session_factory() as session:
           rows = (
               session.query(SearchResult)
               .filter(SearchResult.batch_id == batch_id)
               .yield_per(chunk_size)
           )
           for r in rows:
               yield {
                   "company_name": r.company_name,
                   "company_linkedin_url": r.company_linkedin_url,
                   "name": r.employee_name,
                   "title": r.employee_title,
                   "profile_url": r.employee_profile_url,
               }
   ```

3. Update the `Iterator` import in the typing imports at the top of the file — add `Iterator`
   to the existing `from typing import ...` line.
