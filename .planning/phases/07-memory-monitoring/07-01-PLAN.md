<objective>
Add memory monitoring with circuit breaker to the outreach pipeline.

Purpose: The outreach pipeline processes large employee datasets (thousands of employees across many companies). Without RAM monitoring, the process can OOM-kill silently. This plan adds a psutil-based memory monitor that logs usage at key checkpoints and pauses batch processing when memory exceeds a configurable threshold (default 80%).

Output: Working memory monitor utility, circuit breaker in outreach batch processing, memory logging at 3 pipeline checkpoints, configurable threshold.
</objective>

**Circuit breaker (MON-02):**
The circuit breaker should pause outreach batch processing when memory is too high. Add the check in `_run_search()`, immediately AFTER the post-clustering checkpoint (after checkpoint 2 above). The logic:

```python
# Circuit breaker: check memory after clustering (most memory-intensive phase)
if check_memory_threshold():
    logger.warning(
        "[MEMORY] Circuit breaker: pausing before session creation. "
        "Consider reducing company_limit or employees_per_company.",
        task_id=task_id,
    )
    # Force garbage collection to reclaim freed memory from del statements above
    import gc
    gc.collect()
    log_memory_checkpoint("post-gc")
    # Re-check after GC -- if still over threshold, continue anyway with warning
    if check_memory_threshold():
        logger.warning(
            "[MEMORY] Still above threshold after GC. Continuing with degraded performance.",
            task_id=task_id,
        )
```

Also add circuit breaker check in `_run_send()` AFTER the pre-send checkpoint:

```python
if check_memory_threshold():

        "Reducing batch may be needed.",
        task_id=task_id,
    )
    import gc
    gc.collect()
    log_memory_checkpoint("pre-send-post-gc")
```

Do NOT add circuit breaker to the legacy `_run()` method -- it is kept for backward compatibility and the two-phase workflow (_run_search + _run_send) is the primary path.
