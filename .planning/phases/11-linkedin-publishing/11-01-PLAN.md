  <name>Task 2: Create PublishingService with single/batch publish, error handling, and Kafka events</name>
  <files>src/core/api/services/publishing_service.py</files>
  <action>
Create `src/core/api/services/publishing_service.py` following the established service pattern (see `campaign_service.py` and `content_generation_service.py`):

**Constructor:** `__init__(self, engine_or_url, linkedin_client: LinkedInAPIClient, kafka_producer: KafkaResultProducer)`. Store all three. Create session factory from engine using `create_db_engine`/`create_session_factory` pattern. Load config via `load_config()` for stagger timing settings.

**Method: `publish_single_variant(self, variant_id: str, organization_urn: Optional[str] = None) -> dict`**
1. Open DB session. Load CampaignVariant by `variant_id`. Raise `ValueError("Variant {variant_id} not found")` if missing.
2. Validate: variant has non-empty `content` (raise ValueError if empty). Validate: variant has no `linkedin_post_urn` yet (raise ValueError "Variant already published" if set).
3. Load Campaign by `variant.campaign_id`. Validate campaign status is "active" or "scheduled" (raise ValueError if not -- must be in a publishable state).
4. Resolve `organization_urn` from parameter or config default.
5. Call `self._linkedin_client.create_post(text=variant.content, organization_urn=org_urn)`.
6. Extract post URN from response `response_data.get("id")`.
7. Update variant in DB: set `linkedin_post_urn = post_urn`, `published_at = time.time()`. Commit.
8. Publish success event to Kafka using `PublishResultEvent` schema to `TOPIC_CAMPAIGN_PUBLISH_RESULTS`.
9. Return dict matching `PublishSingleResponse` fields with `status="published"`.

**Error handling in publish_single_variant** (wrap the create_post call in try/except):
- `TokenExpiredError`: Transition campaign to "paused" status using a direct DB update (`campaign.status = "paused"`, `campaign.updated_at = time.time()`). Publish failure event to Kafka with `status="failed"`, `error="token_expired: {str(e)}"`. Re-raise the TokenExpiredError (controller will handle 401 response).
- `RateLimitError`: Retry with backoff. Use `retry_after` from the exception (default to 60s if None). Sleep for `retry_after` seconds using `time.sleep()`, then retry the `create_post` call ONE time. If second attempt also raises RateLimitError, publish failure event and raise. (Keep it simple -- one retry, not exponential backoff).
- `LinkedInAPIError` where "duplicate" or "422" appears in message: Publish failure event with `status="duplicate"`, `error=str(e)`. Return dict with `status="duplicate"` (do NOT raise -- report back to caller).
- Any other `LinkedInAPIError`: Publish failure event with `status="failed"`. Raise the error.

**Method: `publish_batch(self, campaign_id: str, variant_ids: Optional[List[str]] = None, organization_urn: Optional[str] = None) -> dict`**
1. Open DB session. Load Campaign by `campaign_id`. Raise ValueError if not found.
2. Validate campaign status is "active" or "scheduled" (raise ValueError otherwise).
3. If `variant_ids` is None, query all variants for this campaign where `is_selected=1`, `content != ""`, `linkedin_post_urn IS NULL`. If `variant_ids` provided, query those specific variants and validate they belong to this campaign.
4. If no publishable variants found, raise ValueError "No publishable variants found".
5. Resolve org_urn from parameter or config.
6. Iterate through variants. For each variant:
   a. Call `self.publish_single_variant(variant.id, org_urn)`.
   b. Collect result in results list.
   c. If NOT the last variant, sleep for random stagger: `time.sleep(random.uniform(self._config.campaign.post_stagger_minutes_min * 60, self._config.campaign.post_stagger_minutes_max * 60))`. Import `random` at top of file.
   d. If TokenExpiredError is raised during publishing, catch it, add failure result, and STOP publishing remaining variants (campaign is paused).
   e. If any other error, catch it, add failure result to list, and continue to next variant.
7. Return dict matching `PublishBatchResponse` fields: `campaign_id`, `total_variants`, `published` count, `failed` count, `results` list.

**Helper: `_publish_kafka_event(self, campaign_id, variant_id, post_urn, status, error)`**
Create `PublishResultEvent` and call `self._kafka_producer.publish(TOPIC_CAMPAIGN_PUBLISH_RESULTS, key=variant_id, value=event)`. Wrap in try/except to log but not raise on Kafka errors (publishing to LinkedIn succeeded -- don't fail the operation if Kafka is down).

Import from `src.core.queue.config` the `TOPIC_CAMPAIGN_PUBLISH_RESULTS` constant. Import `LinkedInAPIClient`, `TokenExpiredError`, `RateLimitError`, `LinkedInAPIError` from `src.core.providers.linkedin_api_client`. Import `PublishResultEvent` from `src.core.api.schemas.publishing_schemas`.

Use `from loguru import logger` for all logging, consistent with rest of codebase.
